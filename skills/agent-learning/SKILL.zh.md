# Agent 自学习

本文件是 [英文默认入口](SKILL.md) 的简体中文版。

## 从返工和纠正中学习

1. 从当前可见会话及用户提供的材料开始。按需查阅相关项目指令、代码差异、调用方或验证结果。还原原始要求、首次修改的遗漏、触发返工的原因及已经验证的纠正措施。区分观察到的事实与推测的原因，检查反例，并判断问题出在已有规范未执行、流程缺少检查，还是实现本身有缺陷。只有证据显示问题曾多次发生时，才认定为重复问题。
2. 把可复用的经验写成具体动作和检查点。说明何时适用、修改前或修改中要做什么，以及报告完成前如何端到端验证原始要求。对于修改不到位的问题，指出遗漏的入口、调用方、场景或验收条件，并提出能发现该遗漏的检查。每项完成结论都应对应在最终修改上、通过受影响入口执行的检查。可行时，验证回归检查能在修复前发现原始问题，并在修复后通过。说明跳过或无法执行的检查。成功的恢复步骤或失败的尝试只有能改变下次做法时才记录。
3. 收集用户和 Agent 在开发中指出的长期规范。以用户明确要求、项目现行权威指引或相关验证结果为依据。Agent 的建议或一次成功实现不足以确立项目级规则。把尚不确定的规范作为提案，略过临时指示、原始会话记录、敏感信息及项目已通过工程手段落实的经验。结合重复观察和反例判断规则是否成立，将项目特有做法限制在其适用范围。保存前先判断，后续开发者即使遵循现有代码、测试和文档，是否仍可能重复犯错或重新调查原因。如果这些材料已能提供答案，就跳过额外记录。

## 确定位置并提交确认

- 根据问题成因选择改进方式。可机械检测的行为建议用回归测试或自动检查，可重复流程建议写入操作手册或 Skill，需要在动手前知晓的长期项目约束适合写成简短指令。已有规范未被执行时，先查明为什么会被遗漏，再决定是否需要新增规则。
- 采用最小适用范围。起草新增规则前，按语义查找等效规则。获准澄清或替换现有规则时，更新原有来源。根据当前项目证据核对旧规范，发现过时时建议在原处更新。指出无法解决的规范冲突。沿用项目已有的决策记录流程，包括项目已采用的 `agent-notes`。
- 复盘或仅调用本 Skill 时只读。用户要求保存时，可以将已验证的经验写入范围内合适的现有项目文档，同时遵守下方确认步骤。修改业务代码、测试、CI、用户级指令或 Skill 需要对应授权。
- **修改任何 `AGENTS.md` 前，必须由人二次确认。** 先给出目标路径、拟写入的确切措辞或差异、适用范围及其依据，请用户在后续回复中批准这份草案。即使用户初次直接要求更新 `AGENTS.md`，也先提交草案。等待确认期间，根目录和子目录的 `AGENTS.md` 均保持原样，工具或脚本也不得代为修改。待确认的规范不得通过其他指令文件提前生效。
- 只落实已批准的变更，并检查目标文件是否出现了与草案冲突的新改动。措辞、范围或目标位置需要实质调整时，展示更新后的草案并重新取得确认。

## 汇报结果

说明观察到的错误或规范、预防动作和验证方法，以及待确认的规则。获准写入后重新读取受影响文件，检查适用范围、重复条目与引用链接。报告实际保存的内容和位置。有多项值得实施的改进时，指出最能减少下一轮返工的一项，并说明如何在下一次相关任务中验证其效果。没有可复用的经验时，直接说明。
